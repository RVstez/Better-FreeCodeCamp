# Better-FreeCodeCamp

An offline-first learning app for the real freeCodeCamp Responsive Web Design v9 curriculum.
Vanilla JavaScript, no build step, no framework. Run it with `node tools/serve.mjs` and open http://localhost:8080.

## What it is made of
- **Curriculum data** (`public/data/`): generated from the freeCodeCamp export by `tools/build-curriculum.mjs`
  (lessons in their real order, quiz thresholds parsed from the source, nothing invented).
  `tools/verify-normalization.mjs` re-checks the output against the raw export independently (needs `source/rwd-v9-full-export.json`, which is not shipped).
- **Correctness checking** (`public/js/runner.js`, `public/vendor/curriculum-helpers/`): freeCodeCamp's own test runner
  (curriculum-helpers 9.0.1) runs each lesson's original tests in a sandboxed iframe. Proven against all 5,185 tests (`tools/proof/`).
- **Editor** (`public/js/editor-shell.js`, `monaco-loader.js`, `public/vendor/monaco/`): Monaco (the engine freeCodeCamp uses), bundled for offline use,
  with a live preview, width presets (Fit / 768 / 375), font size, reset, copy and full screen. Typed code is autosaved.
- **Progress** (`public/js/state.js`): versioned localStorage with export / import / reset (the ⋯ menu). Storage keys keep their original
  `rvstez-rwd-*` names on purpose, so existing saved progress is not orphaned.
- **Offline** (`public/sw.js`, generated by `tools/build-sw.mjs` on every server start): after the first load the whole app is saved in the browser and
  keeps working if the local server stalls or stops.

## Keyboard
`Ctrl+K` lesson search · `?` shortcut reference · `Ctrl+B` sidebar · `Ctrl+P` / `Ctrl+N` previous / next step · `Ctrl+Shift+G` check (leaves the editor and shows the results) ·
`Ctrl+M` focus the editor → full screen → leave it · `Ctrl+Shift+Y` (`Cmd+Shift+Y`) copy a lesson link or code block · `Ctrl+Q` cycle questions · `Alt+↑/↓` move between answers · `Ctrl+Alt` pick the focused answer.
These are handled in capture phase (`app.js`), so they win over Monaco's own bindings for the same keys (it binds Ctrl+M and Ctrl+G).
Browsers reserve a few combinations on desktop (for example Ctrl+N opens a new window); on an Android tablet with a keyboard they pass through.

**Focus changes wait for the keys to be released.** Leaving the editor, entering it, full screen and step navigation happen once Ctrl/Shift/Alt are up (1.5s at most), because moving focus in the middle of a chord can leave a modifier latched on some Android keyboards (afterwards plain arrow keys select text). Open the app with `?keys` in the address (`http://localhost:8080/?keys`) to show every key event's Ctrl/Shift/Alt state on screen.
**The page follows the cursor.** Monaco only scrolls its own content, so the cursor is kept inside the visible part of the window, and ArrowUp at the very start / ArrowDown at the very end of the code scroll the page on.

## Tests
```
node --test tools/test/state.test.mjs tools/test/progress.test.mjs tools/test/runner.test.mjs     # unit tests (no browser)
CHROME=/path/to/chromium node tools/test/<name>.mjs          # browser tests (Playwright): keys round1 round2 workshop-e2e ui-smoke fonts slowimg offline
```
`offline.mjs` freezes (SIGSTOP) and then kills the server and checks that lessons, the editor and the real checks keep working.

Check `TESTING.md` for guide on testing.

## Decisions worth knowing
- **The test frame needs no network.** freeCodeCamp's runner makes its sandboxed frame fetch its own script from the server, so "Timed out waiting for the test
  frame to load" appeared whenever the server was slow or paused. While a runner is created, that one `<script src>` is swapped for the same file inline
  (`runner.js`). The tests, the evaluator and the sandbox are unchanged.
- **The preview fills its panel and scrolls inside it.** Measuring content height from inside a frame whose height we then change feeds back on itself
  for pages with viewport-relative heights; the frame used to grow on its own.
- **Our shortcuts are captured before Monaco sees them**, so Ctrl+M / Ctrl+G are ours inside the editor.

## Known gaps
- Lesson images are loaded from freeCodeCamp's CDN and need a connection (they show their alt text offline).
- The certification exam is a pointer only in the source export; there are no exam questions to practise.
- Monaco logs an occasional internal "TextModelPart is disposed" console error after very rapid navigation; it has no effect on behaviour.
